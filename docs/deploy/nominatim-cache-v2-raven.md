# Nominatim Cache v2 重写与 Raven 迁移计划

在现有仓库内用 Go + MariaDB 接替 Node.js + SQLite，并给获授权的调用方提供异步批量反查。客户端单点入口由 Raven Nginx 直接转发给 Nominatim Cache。路径、项目分工及切换顺序见 [Nominatim Cache 地点反查迁移说明](map-gateway-place-migration.md)。

2026-11-25 Raven 先从空库预部署，随后导入用户提供的旧 SQLite 归档，尚未切换公共入口。本次实际执行和导入记录见 [Raven 部署执行单](raven-cutover.md)。

## 2. Go 服务与兼容范围

- API 用 `net/http`，MariaDB 用 `database/sql` 和 `go-sql-driver/mysql`。一个 systemd 进程运行 API 与队列 worker。MariaDB 使用独立业务库和专用账号。日常运行账号只获应用读写权限，建表升级走独立命令。
- 保留 `GET /api/reverse` 的同步语义。查到结果仍返回 200，非法坐标保留 400，全部上游失败沿用现有 500 与 `error` 字段。保持长地址 `display_name`、短地名 `place_name` 和质量字段的含义。缓存命中与未命中使用同一选名规则，`coarse` 或 `none` 时短名允许为空。
- 保留缓存查询与人工维护、上游比较、日志和统计以及管理鉴权。管理页、静态资源和管理 API 共享独立的私有入口。公开入口只提供健康检查与对外 API。
- `/health` 保留原有字段，增加 `version`、`commit` 和数据库就绪状态。数据库不可用时返回 503。健康探针只检查应用和数据库，上游成功率由运行指标单独体现。
- 缓存沿用四位小数的 `cache_key`，导入时逐字保留旧键。用 Node 样本核对 Go 对负经纬度、舍入边界和负零的处理，确保迁来的记录仍能命中。统计保留旧累计值，日统计按配置时区聚合，默认北京时间。

## 3. 批量接口与队列

批量查询和单点接口共用缓存与上游调度器。同一坐标共享查询，批次仍按原输入顺序逐项返回结果。

计划新增 `batch_jobs`、`batch_items` 和 `geocode_tasks` 三张表，分别存批次、输入序号与结果、可重试的上游任务。同一调用方用相同幂等键和相同请求重试时返回原任务，换了请求内容则返回 409。队列初版只运行一个 worker，服务重启后从库中继续。

| 接口 | 约定 |
| --- | --- |
| `POST /api/reverse/batches` | 提交坐标列表。初始上限 500 点，可配置。返回 202、`job_id`、已完成数及查询链接。使用独立调用凭据与 `Idempotency-Key` 防止重复提交。 |
| `GET /api/reverse/batches/{job_id}` | 查询完成数、待处理数、失败数及整体状态。 |
| `GET /api/reverse/batches/{job_id}/results` | 按原始输入顺序分页取结果，区分已命中、已查到、无结果和失败。仅任务提交方可访问。 |

1. 提交时按缓存键去重，在 MariaDB 批量查缓存。命中项立即可取，未命中项以事务写入批次和待查任务。保留输入序号，同一点重复出现时每个位置都有结果。每个调用方设待处理数量上限，达到上限返回 429 和重试时间。
2. 每个缓存键最多一个活跃待查任务。worker 领取任务时记录租约和尝试次数，只有当前租约持有者可提交结果。成功时将缓存与任务完成状态一并写入，进程重启后由超时租约恢复未完成项。只对暂时性失败重试，按退避时间和最大次数结束，单点失败不影响整批。已完成批次保留期限初定 7 天，地址缓存单独保留。
3. 单点缓存命中直接返回。未命中可复用符合上游资格的待查任务，并在请求期限内等待结果。调度给交互请求优先级，也给批量任务保留处理机会。状态查询显示最近错误和下次重试时间，便于调用方决定何时再查。
4. 每次请求上游都经过该源的限速，包括重试、换源和后台手动比较。交互与批量共享同一份上游额度。批量缓存未命中只交给明确允许该用途及用量的自建或签约源。公共 OSM Nominatim 与 Photon 演示站默认不进入批量源池。未配置符合条件的批量源时，缓存命中仍可取，未命中项标记 `batch_source_unavailable`。现有公共上游也须按各自条款配置。 [OSMF Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/) · [Photon 演示站说明](https://github.com/komoot/photon#demo-server)

批处理的收益来自批量查缓存、去重和结果复用。假设 500 点里有 60 个唯一点需要请求上游，若一个允许批处理的源每 1.5 秒能发一次，仅请求间隔就约 90 秒，另计排队、响应和重试。客户端提交后查进度，单次 HTTP 超时不用覆盖整批。

## 4. SQLite 打包与 MariaDB 导入

| 旧表 | 导入后保留 |
| --- | --- |
| `cache_entries` | ID、原缓存键、坐标、长地址、结构化地址、原始响应、来源、首次与最近访问时间、命中次数。兼容历史记录缺少 `address` 的情况，必要时从原始响应提取。短名按 v2 规则派生。 |
| `access_logs` | 现存访问记录、坐标、缓存命中标记和毫秒时间戳。 |
| `stats` | 累计请求、命中和未命中计数。保留原累计值，近期日志用于每日趋势。 |

1. **确认旧站实际数据库。** 从进程、服务或容器配置查运行目录、实际挂载和 `DATABASE_PATH`。记录 SQLite 版本、文件体量、三表结构及行数。默认路径 `server/data/cache.db` 用于定位。
2. **旧机生成演练包。** 旧站继续运行时，在旧机使用 SQLite 在线备份接口生成独立 `cache.db`，包含已提交的 WAL 内容。对快照执行 `PRAGMA integrity_check`，记录三表计数、生成时间、文件大小和 SHA-256。把快照和清单打成归档，经 SSH 拷到本地 `data/migration/`，旧机也保留一份备份。迁移回执只记摘要和计数。
3. **在隔离库演练。** 先执行版本化 SQL。缓存键用唯一索引，时间戳存为毫秒整数，原始 JSON 用文本保存。迁移工具从快照分批写入空目标库，按快照校验值识别重复导入。若中途失败，重建隔离库后重跑。正式环境使用新的空目标库。
4. **核对导入。** 对比三表行数、ID 范围、累计统计和按缓存键对比的内容摘要。抽验手工录入、不同上游及过粗地址的历史记录，确认已迁移坐标能命中缓存。记录导入用时，估算切换窗口。
5. **切换时重新打包。** 暂停旧入口接收新请求，等在途请求结束并停止旧应用，再取最终快照。按同一流程校验、传输，导入 Raven 的正式 MariaDB。演练库和正式库分开。

## 5. 发版与 Raven 部署

- 演练使用 `v2.0.0-rc.1`，有变更递增 RC 编号。验收后合并到 `main`，正式 tag `v2.0.0` 指向合并后的实际构建提交。从正式 tag 构建并复验。修复用 `v2.0.1`，向后兼容的新功能用 `v2.1.0`。API 版本与发布标签分别管理。
- 本地 PC 或 WSL 构建 Linux amd64 二进制。发布包包括服务、迁移命令、静态后台、SQL 迁移与校验清单。清单记录发布版本、完整 Git SHA、包校验值和 SQL 迁移目标版本。正式包从已提交源码构建。
- Raven 使用 `/opt/nominatim-cache/releases/<version>/` 和 `current` 软链接。配置放 `/etc/nominatim-cache/`，数据库、归档和迁移记录放数据盘的项目目录。服务使用独立的 systemd unit 和 journald，监听回环地址。现场端口及 MariaDB 实例见 [Raven 部署执行单](raven-cutover.md)。
- 正式库纳入 Raven 的备份流程，备份要能还原到独立实例。切换后每次应用升级前验证待执行的 SQL 和回滚版本对表结构的兼容性。
- Raven Nginx 仅将 `/nominatim/reverse`、`/nominatim/health`、`/nominatim/help` 从公网直接转到 NC。批量接口仍在授权环境试用，管理页和管理 API 经独立回环监听访问。
- 当前测试客户端由用户手动升级。用户验收新入口后可直接撤下 `https://nc.zaitu.cn/api/reverse`，并停止旧 Node。实际停旧和回退按 [Raven 部署执行单](raven-cutover.md) 操作。

## 6. 实施顺序与回滚

| 阶段 | 完成条件 |
| --- | --- |
| 1. 定基线 | 核实旧站启动方式、数据库路径和体量，确认 Raven 端口、MariaDB 和代理入口。记录旧接口样例，更新 API、设计和配置文档后开始实现。 |
| 2. 本地实现 | Go 实现单点、缓存、后台及健康检查。用固定样本验证长短名、坐标舍入和错误契约。用模拟上游验证队列去重、限速、重启恢复、提交重放和部分失败。 |
| 3. 迁移演练 | 旧机在线打包，导入隔离库并核对。RC 在 Raven 私有入口验证接口和回退步骤。按演练结果补齐停写时间、端口和操作命令。 |
| 4. 入口联调 | 验收 Nginx 直连、接口指南、缓存命中、短名、受控上游查询、原有地图服务和后台。批量任务在授权环境独立验证。 |
| 5. 测试切换与停旧 | 用户升级相关客户端并完成地点回归后，停用旧入口和旧应用自启动，保留切换前的快照和程序。关注 5xx、缓存命中率、各源 429 与超时。 |

后续发布优先回退到与当前 MariaDB 表结构兼容的上一版 Go 构建。必须恢复 Node 时，暂停新版写入和批量提交，按 Raven 执行单备份并反向导出独立 SQLite 快照。批次状态保留在 MariaDB，可在恢复 Go 后继续处理。
